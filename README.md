# RBM-Plankton

[![CI](https://github.com/francescopazzocco/rbm-plankton/actions/workflows/ci.yml/badge.svg)](https://github.com/francescopazzocco/rbm-plankton/actions/workflows/ci.yml)

Restricted Boltzmann Machine for unsupervised learning of plankton community
structure from Lake Greifen monitoring data (2019–2024).

**Dataset**: Eyring et al. (2025). *Scientific Data* 12:653 — 5 years of high-frequency
phytoplankton and zooplankton observations from Lake Greifen.
DOI: [10.1038/s41597-025-04988-9](https://doi.org/10.1038/s41597-025-04988-9)

## Quick start

```bash
# 1. Clone & install
python -m venv .venv
source .venv/bin/activate
pip install -e .          # editable install: makes `models` importable, reads requirements.txt
# pip install -e ".[dev]" # add pytest + ruff if you'll run tests/lint

# 2. Place your data (see data requirements below)
#    data/raw/TimeSeries_countsuL_clean.csv

# 3. Run a single training
python code/scripts/train/train.py

# 4. Analyse results
python code/scripts/diagnostic/sweep_analysis.py
python code/scripts/analysis/hidden/hidden_dominant_state.py
```

**You need the raw dataset (`data/raw/`) and trained model weights (`training_runs/`) to actually run.** The raw data is not distributed in this repo (see `.gitignore`). Trained weights are regenerated by `train.py`.

Every location in the working tree is defined once, in `code/src/models/paths.py`.
Set `RBM_PLANKTON_ROOT` to run the pipeline against a tree other than the one
holding the sources.

## Data requirements

Place the raw CSV at `data/raw/TimeSeries_countsuL_clean.csv` (83 taxa columns,
daily resolution, organisms/µL). This file is gitignored — users must provide it.

The pipeline automatically handles:
- Dropping all-zero and fully-NaN rows
- COUNT_SCALE=1000 (organisms/µL → organisms/mL) for numerical stability
- Binarisation (Bernoulli families) at per-taxon median threshold
- Train/val split (85/15, chronological or shuffled)

## Usage

### Training

All hyperparameters are in `code/scripts/train/config.py`:
- `SINGLE_RUN=True` trains one model (default: nb_sigmoid L=6)
- `SINGLE_RUN=False` runs a multi-(family, L, seed) sweep
- `SPLIT = SHUFFLED` or `CHRONO` — decides both how the data is split and the
  run-directory suffix, so the two cannot disagree
- CLI overrides: `--family`, `--L`, `--seeds` (passing `--family` or `--L`
  implies a single run)

```bash
# Single run (default: nb_sigmoid L=6 seed=0)
python code/scripts/train/train.py

# Single run with overrides
python code/scripts/train/train.py --family nb --L 6

# Multi-seed sweep (set SINGLE_RUN=False and L_VALUES in config.py first)
python code/scripts/train/train.py
```

Results go to `training_runs/{family}_L{n}/seed_{k}/`, with a `_shuffled` suffix
on the directory when `SPLIT = SHUFFLED`.

**Model families:**

| Family | Visible | Hidden | Training | Notes |
|--------|---------|--------|----------|-------|
| `nb` | NB | Bernoulli | PCD-1 | Canonical NB baseline |
| `zinb` | ZINB | Bernoulli | PCD-1 | |
| `nb_sigmoid` | NB | Sigmoid | PCD-1 | Recommended — best NLL (LOG-021) |
| `nb_softmax` | NB | Softmax | PCD-1 | Abandoned — collapses (LOG-022) |
| `zinb_sigmoid` | ZINB | Sigmoid | PCD-1 | |
| `zinb_softmax` | ZINB | Softmax | PCD-1 | |
| `bernoulli_median` | Bernoulli (median) | Bernoulli | CD-1 | |
| `bernoulli_zero` | Bernoulli (zero) | Bernoulli | CD-1 | Near-trivial (LOG-005) |

### Pre-training EDA

```bash
python code/scripts/train/dataset_analysis.py
```

Generates 5 figures in `results/01_exploratory/`:
- Daily row sum + rolling median, Lomb-Scargle periodogram, annual/seasonal
  statistics, marginal distributions, NaN structure.

### Model evaluation

```bash
python code/scripts/diagnostic/sweep_analysis.py --split shuffled  # L-sweep → diagnostic_outputs/04_model_selection/
python code/scripts/diagnostic/split_comparison.py      # Chrono vs shuffled → results/tables/
python code/scripts/diagnostic/nan_test_eval.py         # NaN imputation → diagnostic_outputs/nan_eval_extended/
python code/scripts/diagnostic/plot_training_runs.py    # Training curves → diagnostic_outputs/
```

Scripts that read one split at a time take `--split chrono|shuffled` (default
`chrono`) and write shuffled results to a `shuffled/` subdirectory, so the two
splits never overwrite each other.

### Ecological interpretation — hidden units

All outputs go to `results/02_model_analysis/hidden/`.

```bash
python code/scripts/analysis/hidden/hidden_dominant_state.py    # Dominant state timelines + weight profiles
python code/scripts/analysis/hidden/hidden_mean_activation.py   # Mean activation per hidden unit
python code/scripts/analysis/hidden/hidden_cross_model.py       # NB vs BB-median comparison
python code/scripts/analysis/hidden/hidden_pattern_analysis.py  # Binary hidden patterns of one run
python code/scripts/analysis/hidden/rbm_hidden_stackplot.py     # Hidden activation share over time
python code/scripts/analysis/hidden/plot_visible_by_hidden.py --weights training_runs/nb_L6/seed_8/weights.npz
```

These accept `--split`, and the single-run ones also `--family` / `--L`.

### Ecological interpretation — archetype comparison

All outputs go to `results/02_model_analysis/archetype/`. Each accepts
`--family` / `--L` / `--split` (default: resolves the best-converged seed via
`models.io.best_seed_dir`) or an explicit `--weights` path.

```bash
python code/scripts/analysis/archetype/archetype_rbm_comparison.py       # Tables for doc/archetype_rbm_comparison.md
python code/scripts/analysis/archetype/distance_archetypes_rbm.py        # Archetype<->hidden-unit distance heatmap
python code/scripts/analysis/archetype/overlap_archetypes_rbm.py         # Archetype<->hidden-unit overlap heatmap
python code/scripts/analysis/archetype/archetype_closest_rbm_scatter.py  # Closest-archetype scatter
```

`distance_archetypes_rbm.py`, `overlap_archetypes_rbm.py` and
`archetype_closest_rbm_scatter.py` are three near-identical takes on the same
comparison (shared, copy-pasted `sigmoid()`/`compute_visible_activation()`
helpers). `.claude/REORG_AND_VALIDATION.md` (§A-3) recommends consolidating
them into one script with a `--mode {distance,overlap,scatter}` flag; not
done here — this pass only made all three runnable against the current
`training_runs/`/`prof/` layout (they previously pointed at paths that no
longer exist and had no output on disk).

### Reconstruction comparison

```bash
python code/scripts/analysis/reconstruction/compare_model_reconstructions.py --Ln 6 --seed 0
```

Output goes to `results/reconstruction_plots/`. `compare_model_reconstructions.py`
imports its sibling `use_trained_rbm.py` for model loading; both were moved
together to keep that import working. Its own comparison logic is untouched
here — `.claude/REORG_AND_VALIDATION.md` (§0, §A-3) still recommends a
rewrite against the NB/ZINB-only comparison perimeter.

### Archive (one-off plots, gitignored)

```bash
python code/scripts/archive/plot_final_metric_nb.py  # Final NLL vs L (NB+ZINB sigmoid/softmax)
python code/scripts/archive/plot_sigmoid_nll.py      # NB softmax train NLL curves
python code/scripts/archive/plot_zinb_nll.py         # ZINB sigmoid/softmax train NLL curves
```

**Key results:**
- L=6 selected: cumulative ~2.5% NLL/PLL gain over L=3; no gain at L=7
- Both NB-RBM and BB-median independently recover the same two dominant
  ecological axes (summer community, winter community)
- NB uses compositional representation (~30 distinct 6-bit patterns);
  BB-median uses exclusive switching
- `bernoulli_zero` is near-trivial, confirming the median threshold decision
